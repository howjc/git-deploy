# Release Notes v1.8.1

## 变更摘要

相对 v1.8.0：安全修复 Bash/Zsh 静态补全对恶意 Target 名称的本地命令执行路径；收紧 Target 名称校验；并行 FTP 会话建立阶段正确传播 `KeyboardInterrupt`/`SystemExit`；显式 completion install 不再用普通文件替换 RC 符号链接；`FILES_PUBLISHED` 阶段的 Remote Plan 与 Executor 对齐；并将 `bootstrap`/`completion` 纳入 Target 保留字、补全 Empty Directory 恢复门、过期静态补全脚本自动刷新、中断建连时 Sibling 确定性关闭，以及 Changelog URL 修正。

## 安全

### Target 名称与 Shell 补全（P0）

- Target 名称统一为安全规则：`^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`，并继续拒绝 CLI 保留字。
- 完整配置加载与 `completion targets` 原始 TOML 读取使用同一校验函数，非法 Key 不会进入补全候选。
- Bash 静态脚本：动态 Target **不再**进入 `compgen -W`（避免 Word List 二次展开执行 `$()` / 反引号）；改为 `mapfile` 行数组 + 前缀匹配写入 `COMPREPLY`。
- Zsh 静态脚本：Target 以真实行数组 `("${(@f)...}")` 交给 `_describe`，不再经 `${=targets}` 分词。

### 影响

若本地 `deploy.toml` 曾使用含空格、`$()`、`;` 等字符的 Target 名，升级后配置加载将失败，请改为安全标识符后重新部署。

## 修复

### FTP Hybrid 并行 Pool 中断（P1）

- Sibling 建连仅对普通连接异常降级；`KeyboardInterrupt` / `SystemExit` 等向外传播。
- 中断时关闭已打开的 sibling，Stage/Publish 作业数保持 0。

### Completion RC 符号链接（P2）

- `completion install` 对 RC 路径：若为 symlink，则对 **解析后的真实文件** 做原子写，保留 symlink 节点。
- 悬空 symlink 明确报错，不静默替换为普通文件。

### FILES_PUBLISHED Plan/Execute 对齐（P2）

- Pending 阶段为 `FILES_PUBLISHED` 时，Remote Plan **不再**列出 Hybrid Upload（与 Executor 只做 Prune 一致）。
- 对当前应存在的文件做 fail-closed 校验：缺失则 Plan 失败，避免“计划显示上传、实际跳过”的漂移。

### Reserved targets：`bootstrap` / `completion`（P2）

- Target 保留字与 Flat CLI 固定 Action 对齐：`build`、`doctor`、`init`、`bootstrap`、`completion`。
- Config 与 Completion 共享同一组 `CLI_FIXED_ACTIONS`；配置中使用上述名称作为 Target 会加载失败。

### Empty Directory Resume Gate（P2）

- 已发布阶段（如 `FILES_PUBLISHED`）除校验应存在文件外，还校验顶层 Mirror 目录与嵌套空目录。
- 缺失则 Remote Plan / Resume 只读 fail-closed，不自动补建、不推进 Pending、不写 Ownership/State。

### Stale Completion Script 自动刷新（P3）

- 普通 CLI 使用时，若已安装的静态 Bash/Zsh 补全脚本内容过期，会**原子刷新**为当前包内脚本。
- 自动刷新**不修改** `.bashrc` / `.zshrc`（不重写 RC Block）。

### Mid-connect Sibling 确定性关闭（P3）

- `_open_ftp_hybrid_worker()` 在 `connect()` 过程中发生 `BaseException`（含 `KeyboardInterrupt` / `SystemExit`）时，先关闭当前正在构造的 Sibling，再向外传播。
- 与外层已返回 Sibling 的清理语义一致；中断后 Stage/Publish 作业数保持 0。

### Changelog URL（元数据）

- 包元数据 `Changelog` 已指向 `docs/releases/v1.8.1.md`（不再错误指向 v1.8.0）。

## 迁移

1. **静态补全脚本会自动刷新**：从 v1.8.0 升级后，普通 CLI 使用（例如 `git-deploy --version`）即可把已安装的 Bash/Zsh 静态脚本原子更新为安全版本，**无需编辑 RC 文件**。
2. **显式 `git-deploy completion install` 仍可用作保险**：用于重新确认 RC Block 是否已注入，或强制安装/刷新脚本与 RC 标记。
3. 检查 Target 名称是否符合安全规则，且未使用保留字 `build` / `doctor` / `init` / `bootstrap` / `completion`；非法或保留名称需在 `deploy.toml` 中重命名。
4. 包版本为 **1.8.1**。
