# Release Notes v1.8.0

## 变更摘要

相对 v1.7.3：FTP In-place Hybrid 增量 Mirror、Stage-only 校验、可配置并行会话、阶段进度，以及 Shell Tab 补全；并完成发布门禁加固（Pending 兼容、默认串行、补全安全）。

## 功能

### FTP Hybrid 增量 Mirror

- Local State 持久化 Mirror 嵌套路径的 SHA256/Size。
- 默认 `deploy.ftp_incremental_mirror = true`：State hash 未变且远端路径仍存在时可跳过上传。
- **不校验远端文件内容**；漂移时使用 `--full` 或 `ftp_incremental_mirror = false`（强 Mirror，上传全部当前 Hybrid 文件）。
- Remote Plan 明示 `FTP MIRROR MODE` / `REMOTE CONTENT HASH` / `CONTENT PROOF`。

### 业务文件校验

- 默认 Stage RETR SHA256 + Rename Replace（rename-trusted，无 Final RETR）。
- 可选 `deploy.ftp_verify_final = true` 在最终路径再做一次 RETR SHA256。
- Pending / Ownership 元数据仍 Stage+Final 双校验。

### 并行 FTP 会话

- `deploy.ftp_connections`（**默认 1**，范围 1–16）：Stage/Publish 可选并行。
- 先建立全部 sibling 会话再启动 Worker；建连失败安全降级并 WARNING。
- 输出 effective connections。

### 阶段进度

- STAGE / VERIFY / MKDIR / PUBLISH / PENDING / PRUNE / OWNERSHIP / STATE / CLEANUP。
- 非 TTY 对高频 phase 更新采样（约 2s），避免万级文件日志膨胀。
- Cleanup 失败显示 `CLEANUP PENDING`，不再误报 100%。
- DELETE/RMD 经统一 Progress note 输出。

### Shell Tab 补全

- `git-deploy completion {bash,zsh,targets,install}` + argcomplete。
- **普通 CLI 不再自动改写** `.bashrc`/`.zshrc`；显式 `completion install`。
- 原子写（tmp + fsync + replace）、安装锁、路径 `shlex.quote`、Zsh `#compdef`。

## 兼容与修复（相对未发布 main 功能）

- **Pending Schema 2 Hash**：Mirror 嵌套 State key 不再进入 `local_manifest_hash` 的 `outputs` 侧，与 v1.7.3 提交前 Pending 可继续恢复。
- **默认并行改为 1**，避免共享主机因默认 4 连接失败。
- **停止静默改 RC**，消除非原子覆盖用户 Shell 配置的风险。

## 迁移

1. 从 v1.7.3 升级前，尽量在旧版本完成所有 FTP Pending（`PREPARED` / `FILES_PUBLISHED` / `PRUNED`），或确认无 Pending。
2. 需要并行时显式配置 `deploy.ftp_connections = 4`（等）并在目标 FTP 上做并发 canary。
3. 若面板/备份可能改写受管文件，定期 `git-deploy <target> --full` 或关闭增量 Mirror。
4. 启用补全：`git-deploy completion install`（可先备份 RC）。
5. 包版本为 **1.8.0**，勿再以 1.7.3 构建当前源码。

## 配置速查

```toml
[deploy]
retries = 3
retry_delay = 2
ftp_connections = 1              # 默认串行；并行需显式提高
ftp_incremental_mirror = true    # false = 强 Mirror
ftp_verify_final = false         # true = 最终路径 RETR
```
