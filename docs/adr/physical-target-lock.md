# ADR：暂缓跨仓物理目标本机锁

- 状态：Accepted（暂缓实现）
- 日期：2026-07-17
- 适用版本：v1.2.2

## 背景

同一个 Thin Workspace 已在 Build 前拒绝同 Endpoint 上相同或父子嵌套的 Remote Root，并为每仓获取 Git Common Dir 内的 Target Lock。但两个终端分别从不同仓库启动独立命令时，各自的仓库锁无法发现它们配置到了同一个物理 Root，远端操作仍可能交错。

## 决策

v1.2.2 不增加 `$XDG_STATE_HOME/git-deploy/targets/<fingerprint>.lock`。当前产品定位是个人单控制器，推荐通过一个 Workspace 管理相关仓库，并明确禁止多个发布器同时管理同一路径。轻量补丁不引入新的全局锁生命周期、过期恢复和身份规范。

本决策不把现有仓库锁描述为物理目标互斥，也不保证跨设备部署互斥。

## 原因

- 本机锁无法解决另一台设备或服务器侧发布器的并发，只能覆盖单机进程。
- Endpoint fingerprint 涉及 Alias 冻结时机、Host 大小写、不同主机名指向同一服务及 ProxyJump 等身份边界。
- 崩溃后的锁恢复、PID 重用和 XDG 目录权限需要独立设计与故障测试，不应混入 FTP/Build 收口补丁。

## 后续触发条件

出现以下任一情况时重新评估：

- 日常工作流需要从多个独立仓库命令发布到同一服务；
- 真实使用出现同机并发覆盖事故；
- 产品开始提供受支持的并行或后台发布入口。

未来实现至少应覆盖：规范化 Endpoint/Root fingerprint、`0700` 状态目录、原子非阻塞获取、持锁者诊断、崩溃自动释放、同进程 Workspace 去重，以及不会宣称跨设备互斥。
