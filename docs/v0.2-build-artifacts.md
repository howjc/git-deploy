# v0.2 构建产物与秘密安全

v0.2 在精确 Git tree 的隔离 worktree 中构建产物，并将 source 与 artifact 纳入同一部署、验证、状态推进和回滚事务。Docker 只是本机构建后端，远端服务器不需要 Docker。

## Project 与 remote 覆盖

项目级 `build` 和 `artifacts` 是公共默认值。`projects.NAME.remotes.REMOTE` 下出现的 `build` 或 `artifacts` 会分别整体替换默认值，不对 commands、env 或数组做隐式深合并。plan/build 会显示最终配置来源。

生产专属秘密构建应只放在 prod override，避免 dev 继承：

```toml
default_remote = "dev"

[remotes.dev]
protocol = "sftp"
host = "dev.example.invalid"

[remotes.prod]
protocol = "sftp"
host = "prod.example.invalid"

[projects.official]
repository = "."

[projects.official.remotes.dev]
remote_root = "/srv/dev/official"

[projects.official.remotes.prod]
remote_root = "/srv/prod/official"

[projects.official.remotes.prod.build]
runner = "docker"
commands = [["composer", "install", "--no-dev", "--no-interaction"]]
timeout = 900
env_allowlist = ["COMPOSER_AUTH"]

[projects.official.remotes.prod.build.docker]
image = "composer@example-sha256-digest"
platform = "linux/amd64"
network = "none"
pull_policy = "never"

[projects.official.remotes.prod.build.onepassword.env]
COMPOSER_AUTH = "op://example-vault/example-item/example-field"

[[projects.official.remotes.prod.artifacts]]
source = "vendor"
destination = "vendor"
kind = "tree"
```

image 和 `op://` URI 是不可用占位符。实际配置应使用可信镜像的不可变 digest，以及最小权限 vault 中的 reference；不要把解析值写入 TOML。

## Host runner

Host runner 直接执行 argv，不经过 shell；只传递 `env_allowlist` 中声明的变量，并使用隔离 HOME。输入来自计划 target tree，主工作区脏文件不会进入产物。

```toml
[projects.official.build]
runner = "host"
commands = [["npm", "ci", "--offline"], ["npm", "run", "build"]]
timeout = 600
cwd = "."

[[projects.official.artifacts]]
source = "dist"
destination = "public/dist"
kind = "tree"
```

隔离 worktree 不是操作系统沙箱：Host 构建代码仍拥有当前用户可访问的 filesystem 和 network 权限。只对可信 revision 使用 Host runner。

## Docker runner

Docker runner 先 inspect 镜像，并把解析出的不可变 image ID 纳入 build fingerprint。建议直接配置 digest；默认使用 `network = "none"`、`pull_policy = "never"`。只有构建确实需要网络时才选择 `bridge`，只有允许拉取缺失镜像时才选择 `missing`。

容器只挂载精确 worktree，使用当前宿主 UID/GID、`no-new-privileges` 和 capability drop；不挂载仓库、HOME、SSH Agent、Docker socket 或 state，也不接受任意 `docker run` 参数。成功、非零退出、timeout 和 Ctrl-C 都会停止并删除命名容器；清理失败会在连接远端前阻断，并保留不含秘密的容器 ID 供显式清理。

Docker daemon/root 管理员不是秘密隔离边界。普通环境变量会出现在存活容器的 `Config.Env`，daemon 权限主体可以 inspect 读取。git-deploy 只承诺自身输出脱敏和可靠删除容器，不承诺秘密对 daemon 不可见。

## 1Password CLI

`build.onepassword.env` 只接受变量名到 `op://` reference 的映射。变量名必须同时出现在 `env_allowlist`，且不能以 `OP_` 开头。Host 使用固定 `op run --` 包装构建 argv；Docker 使用 `op run -- docker run ... --env NAME`。两条路径均不经过 shell，不使用 `op read`、`op inject` 或 `--no-masking`。

`OP_SERVICE_ACCOUNT_TOKEN`、`OP_CONNECT_*`、`OP_SESSION_*` 等认证变量只提供给 `op`，进入 Host 构建进程或 Docker client/container 前全部移除；构建进程只得到声明的变量名和值。

自动化环境应使用只读、最小权限的 1Password service account，并从进程环境或 CI secret store 提供 token。git-deploy 不负责登录、管理 vault/item，也不会向远端 post command 注入秘密。

启用 1Password 后固定 bypass artifact cache，因此 secret rotation 必定重新构建。state、manifest、fingerprint 和日志只记录 provider/变量名等摘要，不记录 reference URI、认证 token 或解析值。

## Build、dry-run 与 artifact 边界

显式本地构建不连接远端，但会写该 target 的受限 build cache：

```bash
git-deploy build official --revisions COMMIT --remote prod
```

普通预览不会创建 worktree、运行 Host/Docker/op、写 cache/state 或连接远端：

```bash
git-deploy deploy official --revisions COMMIT --remote prod --dry-run
```

它只显示 target tree、runner、命令摘要、配置来源、artifact destinations、秘密变量名和信任警告。`--dry-run --check-remote` 可增加只读远端检查，但仍不会构建或调用 op。

Artifact collector 只接受 worktree 内的相对 file/tree，拒绝绝对路径、`..`、symlink、submodule、FIFO、socket 和 device。source/artifact 或 artifact/artifact 目标路径冲突会在远端连接前拒绝。首次没有可信 artifact manifest 时，只能从已知 current source tree 重建 baseline，或通过已验证 empty bootstrap 建立空基线，不能 adopt 未知远端 bytes。

构建脚本一旦获得秘密，就可以主动读取它或写入产物。git-deploy 不扫描 artifact 内容，也不提供 DLP 保证；只给可信 revision 最小权限秘密，并由项目自己的制品扫描和发布门禁检查产物。
